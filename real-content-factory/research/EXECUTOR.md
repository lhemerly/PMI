The reusable research runtime supports the Bonsai research profile and a fixed interval-union correctness evaluator with configurable finite workflow budgets. It reuses the owned CPU transport, admission and minimal runtime; arbitrary command execution and unrelated factory paths remain held. Configuration files and source seals establish scope and integrity, not platform approval.

The unchanged authored CPU qualification passed 884/884 frozen cases: [FIRST-QUALIFICATION-VERIFICATION.json](FIRST-QUALIFICATION-VERIFICATION.json) and [FIRST-CORRECTNESS-RECEIPT.json](FIRST-CORRECTNESS-RECEIPT.json). Its preserved [bundle](runtime-evidence/attempt-v4/bundle-manifest.json) and [posthoc validation](runtime-evidence/attempt-v4/posthoc-calibration-validation.json) do not constitute a fresh run or application result. The installed suite passed 433 model-free tests. ## Entry, scope and ownership

[Runtime commands](RUNTIME.md) are `research-mode-plan`, `start`, `status`, `pause`, `resume` and `cancel`. Plan and status perform no workload launch. The runtime binds each launch to an immutable run configuration, numbered attempt, exact model/role/stage or candidate/source/evaluator request, persisted reservations and finite remaining budgets. Normal platform review remains separate. The historical fixed demonstration's 18 calls, three generated requests and 45-minute outer limit are preserved as that attempt's scope, not a project ceiling. Historical consumed reservations are not reopened by the reusable interface.

`CoordinationOwner` acquires the existing CPU lock and factory lease once per attempt. Laboratory ownership and `CPUAdmission` validate and borrow the retained handles instead of reacquiring them. The outer supervisor keeps duplicate descriptors until independent owned-process cleanup completes. Closing child copies does not explicitly unlock the supervisor's copies. Do not wrap live entry in another flock of the CPU lock. Model-free regression uses the shared external test flock.

The correctness runner uses the actual `CPUAdmission`, `CPUOwnedTransport` and `BubblewrapCorrectnessRunner` classes. A model-free direct-constructor regression covers their import/wiring after the historical `OwnedTransport` import failure. The runner accepts only exact persisted generated requests through active process-local authority. Neither a CLI flag, serialized JSON nor a seal grants arbitrary command or model execution. The benchmark evaluator and generic correctness launch remain held outside their separately reviewed scope.

## Minimal runtime and CPU limits

`runtime_bundle.py` copies only explicitly listed regular-file bytes matching reviewed hashes into a read-only runtime and verifies the exact inventory. It does not call `ldd`, run Python, install packages or change system files. The completed authored qualification supplies observed packaging/bootstrap evidence for its exact inventory. Research execution reuses `/tmp/pmi-correctness-runtime-v2` and the pinned `/tmp/pmi-first-correctness-v2/interval-manifest.json`, rechecking bytes, modes and identity rather than repeating packaging or bootstrap.

Without a shared owner, `CPUAdmission` holds `/tmp/cpu-coordinator-6t3yfB/test.lock` nonblockingly through release. With a shared owner, it borrows the verified handle and still performs fresh admission. The two-second CPU admission window requires 16 GiB available RAM and checks pressure, paging and counter continuity. Runtime floors and limits remain 12 GiB available RAM, 256 MiB aggregate sandbox RSS, 512 MiB per-process address space, five seconds CPU and ten seconds wall, one-core affinity, bounded files and 64 KiB per stream. Artifacts are limited to 16 files and 2 MiB. The 60-second experiment-stage allowance covers admission/controller work without expanding sandbox limits. Existing child-only no-core policy and kernel/core-pattern checks remain unchanged.

Bubblewrap unshares user/PID/network/mount/IPC/UTS/cgroup namespaces, drops capabilities, creates a new session and binds child lifetime to its parent. Only the reviewed minimal runtime and candidate snapshot are mounted read-only; `/work` is writable, `/tmp` is a private 2 MiB tmpfs, `/proc` belongs to the new PID namespace and `/dev` is minimal. Home, credentials, network, host sockets, evaluator answers and receipt paths are not exposed. Seccomp denies incompatible/x32 ABI, process creation, namespace/network access and selected privileged interfaces. Source restrictions are an additional constraint, not confinement.

The candidate is blocked before exec while the controller verifies and pins the PID namespace handle. Fixed argv, `shell=False`, a clean environment and reviewed filter/status/handshake descriptors constrain transport. It captures streams incrementally, watches parent identity, resources and namespace members, checks namespace/exit records and signals only an unreaped owned launcher or fingerprinted members of the pinned namespace. Missing observability, setup failure, timeout, resource stops or incomplete cleanup block acceptance.

Namespace scans exclude only stable tasks born strictly before the verified launcher creating a fresh PID namespace. Equal/newer/unknown births and unreadable potentially relevant tasks remain conservative failures. This inference applies to the fixed fresh-namespace plan, not joining an existing namespace. Tests cover birth ordering and races. CPU V1 remains failed evidence; the separately reviewed CPU V2 bootstrap and authored run establish only their exact observed scope. Hostile exhaustion and supervisor parent-death behavior remain physically unqualified.

Artifacts are collected only after verified cleanup: regular relative files, no symlink/hardlink roots or entries, bounded sizes, content hashes and mutation checks. Runtime/workspace ownership and workload/controller/helper identities remain pinned.

## Model stages and postflight coverage

`bonsai-stock` with `bonsai-research-v1` uses 4,096 context tokens, 512 output tokens for calibration/generation/evolution and 128 for other roles. Each actual prompt requires a conservative rendered-byte fit receipt with the exact role output reserve. Model/native/template/runtime identities, DirectIO loading, automatic fit with a 1,536 MiB margin, fixed sampling and RX 6600 XT/Vulkan0 guards remain pinned. Admission requires 16 GiB RAM; the running RAM floor/RSS bound is 12 GiB, address space 16 GiB and global VRAM 7 GiB. Model admission uses a 30-second observation window; host/GPU execution guards remain 60/50 seconds. A model/calibration stage is capped at 120 seconds; user workflow budgets do not expand it. Generic 64-token settings and unrelated holds remain unchanged.

The research postflight policy changes only a passive `coverage/count/duration` failure. It requires actual finite timestamps spanning 20–21 seconds, strictly positive adjacent gaps no greater than one second, and re-evaluates every non-coverage passive condition. Combined, unknown, resource, identity, paging, pressure, thermal or other failures still reject. It records a separate coverage-policy receipt; an arbitrary saved label cannot suppress another failure. The successful original passive path and unrelated speech semantics remain unchanged.

Historical V4 captured 40 samples over 20.111494875 seconds, with a maximum gap of 0.516279023 seconds. The sample-count rule rejected that elapsed window. Forty samples are the historical observation, not a new universal required count. Posthoc validation checked saved data and disclosed an exit-time telemetry observability race; it made no fresh native invocation or postflight measurement and did not turn the old failed application operation into a successful receipt.

`test_demo_postflight.py` covers the captured window and rejects short/long coverage, nonfinite or regressed time, excessive gaps, hidden or combined failure reasons, resource/identity stops and missing evidence. These model-free checks validate policy behavior. Live-v1 attempt 2 separately recorded accepted calibration and release (`RealTextAndReleasePass`) under the current policy; it does not establish that every later stage or resource condition will pass.

## Deadlines, persistence and lifecycle

Each runtime attempt has an absolute supervisor deadline derived from remaining workflow time, a separate 120-second calibration allowance and 180 seconds reserved for cleanup. Remaining workflow consumption is carried across attempts. Per-kind guards remain 120 seconds for models and 60 seconds for experiment stages. Parent credentials, an inherited sequenced socket and retained lock descriptors bind the child. Model dispatch uses a sealed controller-owned memfd tied to the exact request hash, role, model, process birth identity and deadline; native execution verifies controller ancestry and the reviewed entry. This application capability boundary is not a platform authorization service.

The supervisor uses fingerprinted owned-process cleanup without broad process-name killing. Missing cleanup evidence prevents success and continuation. Tasks reserve before external work; an uncommitted reservation is uncertain and cannot be automatically retried. Source/model-free tests cover scoping, counters, exact requests, cleanup and deadline handling but do not prove hostile-stop behavior.

Pause stops only between committed tasks with no in-flight work. The existing workflow stays `ready`; a later attempt must prove the previous supervisor released ownership and cleaned up. Completed source, prompt, response, receipt and ancestry records remain immutable. Resume cannot replace configuration or reset consumed workflow budgets. Cancellation is permanent. A calibration-only attempt without a workflow database may be explicitly resumed after verified cleanup; an existing blocked/terminal/uncertain workflow cannot be relabeled as that case. Each eligible new attempt calibrates separately. Model-free pause/resume and clean-preworkflow tests do not establish a successful physical lifecycle run.
